# 推广日期、费用分摊与补款关联的证据防线

## 不能用总额对齐代替业务正确性

推广控制总额会抵消部分错误分摊，因此验收必须同时核对来源月份、商品归属、控制池及导出。
`source_period` 留在每条推广事实中；发布前检查已入账事实的月份与原始日期一致。
新接入的推广模板若丢弃日期列必须报错，不能退回首个匹配商品订单的月份。
没有可验证日期或范围而订单跨月时，不允许自动跨月归属。

已覆盖的日期表达：日明细日期、紧凑 `YYYYMMDD`、同月 `YYYYMMDD~YYYYMMDD` 或「至」区间。
跨月区间没有逐月费用依据时保留为待核对，不按天数或订单数猜分。

## 完整重复和范围重叠分别处理

推广整表业务指纹包含全部原始字段、行顺序和重复次数，只排除当前计划「是否已删除」状态。
同店、同账期、同模板且指纹一致的两份来源只计一次；原文件及保留来源哈希均留档。
其他存在同商品同日重叠的推广文件不能直接相加，必须核实是否替换或独立范围。
以“推广”命名但实际是其他业务表的上传不能当成推广费用为零。
此类完整性问题阻止结账和核定实发，不接受“忽略”作为处理方式。

## 不重复记账的分摊证据

事实与导出区分：直接入账、已含全店分摊、真正未入账。
未直接匹配的原推广行保留原金额，但贡献额仍为零，因为控制行已记入其费用。
「已含分摊」页签给出控制文件、工作表及行号；这部分不能再次加总。
只有“进了账”视图与报表总额作对账差额比较，其他筛选集合不显示虚假缺口。
匹配商品不足并不因此视为个人归属已经核定；店铺总额与个人商品归属分开解释。

## 部分入账不等于完整核定

抖音/淘宝推广新增经业务确认的 `allocate.unmatched: store_wide` 口径：原表或单月文件证据明确本店当月，但商品 ID 未匹配本月有效订单时，按 PDD 现有方式分摊到本店当月有商品 ID 的有效订单明细，优先原始订单明细，无原始明细时才使用实时订单。
此规则不适用于收入、成本身份不明或缺少月份的记录，也不因当前界面选择月份而推断发生月。没有本店本月有效分摊订单时仍待核对。
原始商品 ID、文件、行号与金额不改写，不伪造控制总额行；每条原费用只贡献一次，单列“全店分摊入账”及分摊依据。已有全店控制总额覆盖时不建立第二个分摊池。

不可核定的费用节点保留 `available=false` 和原有结账/实发阻断；有真实已入账事实时单独提供 `verified_partial`。
部分金额必须取已认领事实的 `contribution`，不取原表总额；没有已入账行时保持未知，不补零。有真实正负相抵记录时可以显示已入账零。
利润、比例和多指标综合数不以简单加总伪造部分金额。
推广非零行未入账且没有“已含全店分摊”依据时，完整费用继续待核对，不能被另一份有入账的表掩盖。
缺少月份的提示必须包含源文件与工作表；未匹配商品与已有商品但本月无有效分摊结果分别解释。
看板显示已入账部分和完整金额待核对；下钻接口在分页、筛选和空结果时仍携带同一核定状态，并按文件汇总未入账原因。
不通过删除旧表、猜测账期或放宽确认门槛消除提示。历史冻结快照和已核定实发不随展示改进而改写。

## 补款自动互证的边界

只在月表明确标记“用户向商家打款”、有 SS 业务编号、完整流水号、原订单在平台订单导出中存在时采用该原订单引用。
旧版关联引用不得同时作为另一真实原订单出现在订单导出中。
同店、精确时间、科目、有符号金额及唯一流水证据必须一致；科学计数法仅作与完整流水的精度兼容校验，不恢复丢失位数。
互证只排除另一份重复来源，不修改原始文件、原始金额或已核定实发。

## 人工核对闭环

店铺账期页提供“流水关联核对”。同一完整事件若金额、时间、科目不一致，不能人工选一个金额放行。
可确认的候选必须是本店本月完整留档的记录，并已匹配原订单；不能输入任意订单或金额。
核对人、确认勾选和至少8字依据必填，按填写内容留档，不冒充登录身份认证。
提交重新检查最新核算、引擎/模型版本、源文件集合及原文件校验和；已结账或过期资料拒绝确认。
决策严格写入 `config_log`，审计失败则不保存；源组成员、字段或上传变化后，旧核对不自动套用。
重算后才更新已入账数据；重算失败明确保留已保存收据并允许重试，不能声称已核定。
撤销同样追加审计并重新核算，不删除历史依据。已结账和已核定实发仍受原有冻结规则保护。

## 验证入口

- `test_evidence_guards.py`：多模板月份、漏绑定、范围、重叠、完整重复及补款反例。
- `test_statement_review.py`：确认、过期、跨店期、金额冲突、源文件损坏、审计失败、撤销、变更组不复用。
- `statementReview.test.js`：确认条件与“保存成功但重算失败”的状态区分。
- 上线检查需使用生产原表复算，逐文件检查 7 月没有 6 月入账行；按直接与间接计入状态核对导出，不仅比较合计。
