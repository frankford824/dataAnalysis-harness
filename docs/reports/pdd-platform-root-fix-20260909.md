## 根因及修复

| 问题 | 处理 |
| --- | --- |
| 结算日、退款日或补发单创建日被用于确定月份 | 订单关联指标采用原订单日期，保留原始发生日和来源行号 |
| 无订单号的批量罚款、返费被留在未归集明细中 | 仅空订单号收支按账单发生日期归集，来源说明明确标注 |
| 异常订单号继承文件名里的月份 | 禁止用文件月份兜底；取键失败也不能视作原表没有订单号 |
| 合单导出将主单上的多个单号写入每个商品行 | 优先使用商品行原平台订单号；只有单一有效主单号才可补充缺失的行单号 |
| 蓝旗没有进入变更识别和成本输入 | 采集、API、快照、台账保留旗帜，旗帜变化触发更新 |
| 金额确实为零的退款行消失 | 保留真实零金额记录，空金额不伪装为零 |
| 当前价、参考价被当作历史成本 | 按原下单日、成本所属公司和历史有效区间取价；无依据则待核价 |
| 原套餐多个组件共用商品行号，保存时互相覆盖 | 按原内部商品行归组，汇总全部原组件数量与历史价 |
| 已展开单品仍保留套餐来源标识，被误认成整套商品 | 根据当前商品编码判断是否已展开，保留套餐来源用于回查 |
| 被替换的旧商品行仍计入成本 | 计算仅取当前商品行；原成本证据保留，订单台单独展示历史商品行 |
| 整行成本缺失时未进入待核价 | 对缺少成本记录的实际商品补建待核对项，不补造金额 |
| 缺价按零处理，利润和提成仍能出数 | 待核价单独存储；相关利润、提成不出确认金额，结账受阻；明细支持搜索、分页、导出 |
| 接口读取异常返回空列表 | 返回失败状态，界面支持重试；切单不会沿用上一单明细 |
| 商品编码带斜杠导致增量 API 取错路径 | 实体路径支持完整商品编码；目录事件不逐条触发完整价格读取 |
| 增量记录字段类型混用导致导入失败 | 按快照字段定义构建增量，保留长编号及嵌套信息 |
| 来源版本附带组件摘要时被当整数解析 | 单独解析序号与摘要；相同序号但组件依据变化仍触发更新 |
| 单店重算把共享文件中的其它店铺切片存入本店 | 保存前按店铺限定；模拟计算使用相同限制 |
| 售后商品查询扫描整张商品表，快照生成慢 | 先限定涉及订单，再计算订单内关联；同结果实测查询由 2.484 秒降至不足 0.001 秒 |
| 补发时间被用于选择提成比例版本 | 保留原下单月份；缺少原下单时刻时，不套用补发时刻的比例 |
| 重复抓取未变化订单的原组件 | 保存原组件与订单版本，版本未变化时复用；有变化才重新读取 |
| 旧发布流程重新写回参考价 | 安装历史取价规则后，不再重放会恢复参考价的旧迁移 |
| 历史价查询批次过大，一直在同一批商品报 502 | 统一限制每次最多 10 个商品，顺序查询；任一批失败则整次明确失败，不把未查完部分记成缺价 |

最后一项已在线复现并回测：2026-06-01、公司 10562500 的同一组 30 个商品整批查询返回 502；拆成 3 批后全部成功，得到 28 个历史价及 2 个明确缺记录的商品。发布后的公共取价入口调用同一组 30 个商品也已成功，原组件取价和后台补查均使用这一入口。
