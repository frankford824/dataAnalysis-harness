## 已实现的修复

1. 原始平台订单确定收入、服务费、营销费用和推广分摊对象。补发记录参与补发成本核算，不再分走正常销售记录的收入。
2. 补发归属细化到售后标记和内部商品行。同一个售后标记关联多个原订单时，不再把整批商品归给其中一个订单。
3. 发货前售后按实际子订单和商品行排除成本。主订单存在“发货前售后”标记不等于整单所有商品都应清零，已经发货或实际退回的商品分别处理。
4. 淘宝天猫、抖店和 PDD 成本统一校验下单日历史单价、货主、商品、数量和原订单身份。当前单价不能替代历史单价；缺历史、日期冲突或证据不一致时列入待核价。
5. 台账向订单台提供有原文件哈希和行号的下单日期。补发沿用原销售订单日期核价，不能使用补发创建日期。已导入四家店铺 72,868 个确认过的日期键。
6. 套餐组成保留原始组成证据，退回拆开的单品时按原销售历史成本核对。原成本未核实的情况下，不能先计入退货成本冲回、抬高利润。
7. 缺价行保留在核价列表及导出中，显示原下单日期和数量，并阻止利润、提成及结账产生确定金额。人工定价有日期、货主、商品和数量约束；已有真实历史价格后可重新核算未冻结记录。
8. 台账后台刷新保留当前筛选、核价抽屉和搜索词，失败时保留已显示数据并提示状态，恢复后继续更新。
9. 增量同步改为批量携带成本数据，先校验实体身份再推进消费位置。2000 条实库批量查询为 1.703 秒，避免逐订单请求放大。
10. 订单台实时推送中的同步看板查询阻塞了接口事件循环，已移到后台线程。同步接口使用独立线程容量和连接池，版本与轻量健康检查不再每次统计全库质量数据。详细质量检查仍保留独立入口。
11. 磁盘不足时提前阻止新计算结果落盘，保留原结果。三份旧 QA 数据库经 SHA256 校验迁移到 C 盘归档；未移动或删除生产数据库、原始输入文件和已结账记录。
