# 运费复核页面

入口：侧栏“运费复核”，以及账期损益表的“发货运费”。支持月份、店铺、平台范围。

本次只增加已有核算记录的只读对照，不执行逐笔运费审计、重算、补扣、结账更正或提成调整。

## 金额与状态

- 账内已计入：已结账店铺使用结账原记录，人工核定结账优先使用留档金额；未结账店铺使用当前试算。
- 后续试算：使用同一店铺、月份最新保存的试算。来源同步、留档和金额完整后才允许对照。已结账无后续试算、资料不完整或没有完整金额时，金额保持未知，不显示为零。
- 试算差额：完整试算减账内金额。尚未核实，不代表应补扣金额。全范围有一店不可比较时，不展示范围总差额；“试算有变化”组可展示该组净变化，并列出增加、减少的店铺数，避免相互抵消被当成无变化。
- 商品分摊待核对：只读取完整试算中发货运费的分摊待核对项。费用已在店铺或订单层保留，不能重复补扣。
- 试算资料未齐：描述该次试算的来源或留档状态，不承诺后台任务正在运行。更新按钮只读取已有记录。

首页按问题归组到店铺；原账与后续试算在依据抽屉中按准确编号切换，时间、编号和逐行来源按需展开。此处费用转为正数显示，退费冲减允许负数。

## 一致性

页面读取返回范围校验值；CSV 导出固定同一月份、平台、店铺、问题组与校验值。依据变化时拒绝导出旧结果并要求刷新。缺失金额留空，保留状态、分摊说明和记录编号供追溯。

后台检查新记录只提示“有新核算结果”，不静默替换正在核对的数据。切换月份或店铺清除旧数据和抽屉；URL 保存当前范围，刷新后保持一致。

接口仅 GET `/api/freight-review` 与 `/api/freight-review/export.csv`，没有财务写入接口。


## 包裹试算：聚水潭商品金额规则

商品金额口径自 `shipment-erp-goods-amount.v2` 引入，后续版本继续沿用。本包运费按本包实际发货明细的
聚水潭“商品金额”（订单接口 `line_amount`，源自 ERP `order_item.amount`）
占比分摊。该字段是行金额，不再乘数量、不扣退款，不使用平台实付、原表分配率、
商品成本或 ERP 主单金额替代。拆包只汇总本包的行；同一平台子单的套装明细按金额汇总，
并保留各 ERP 明细编号、SKU、名称、数量、商品金额作为依据。

单商品直接归属；多商品金额缺失、非法、为负或总额为零时待核。明确为零的商品在
包内总额大于零时分摊零元。补发使用本次发货明细的商品金额，缺失时不借用原单金额。
退费仍需原分摊依据，来源重复、跨店或身份冲突的检查继续保留。

新规则仅影响新生成的独立包裹试算，不更新原账、已结账快照和提成。
旧记录仍按原规则展示，规则变化后页面提示重新试算；不把旧结果改标为新规则。

### 定制实物与旧虚拟标签

“专拍”是购买方式，不是虚拟商品属性。旧采集规则曾因名称含“专拍”而将定制海报、
KT板误标。新包裹试算只对这一旧标签作有限兼容：名称含“专拍”且不含邮费、运费、
差价等费用词，同时有普通商品 SKU、运单、发货时点及已发货/完成状态时保留其发货明细。
其他虚拟标记不自动放行。编码、成本或收入本身不作为推翻虚拟属性的通用依据。

有运单但明细全部被非实物标记过滤时，显示“有发货记录，明细被标记为非实物，需核对商品属性”，
与“未找到实际发货记录”区分。费用明细不参与实物包裹的分摊权重或发货冲突判断。

### 同运单退差额

规则 `shipment-erp-goods-refund.v3` 将本次资料中同一包裹的负数运费，关联到扫描时间
不晚于它、且已成功分摊的正数收费，沿用完整目标和分摊比例冲减。多条正数依据只有在
目标和比例一致时才可使用，全部原收费编号、时间及留档行保存在冲减记录中，可从详情
回查，CSV 也保留依据编号。原正负两条记录不合并、不删除，合计为净运费。

例如同包单商品 15.48 元收费和 -3.10 元退差额，分别分摊 +15.48、-3.10 元，净额 12.38 元。
v3 在缺少本期正数收费时仍待核；v4 补齐了这种情况：有原收费分摊依据时优先沿用，
没有原收费时，只要包裹和商品归属明确，单商品直接冲减，多商品按本包聚水潭商品金额冲减。
不把缺少本期正数收费等同于退差额不能计入。来源、身份或金额依据仍不明确时保留待核。
费用归属仍使用各行自己的账单扫描月份，不把冲减改记到原收费月份。正式账目和提成不回写。


### 同运单多笔费用与待核展示

`shipment-erp-goods-multifee.v5` 保留同账单中同一运单的不同收费。仅运单、扫描时间相同
不足以判重；金额（含正负方向）、账单结算对象也相同的行仍作为无法区分的重复候选。
同一组中独立的其他收费不受这些候选牵连。相同完整账单的重复上传仍按原文件/规范内容
去重，跨文件的重叠来源仍待核，不把它们自动当作额外费用。

YT7625530235832 的 1.70、1.00、0.60 元应分别分摊，合计 3.30 元；不能仅因后两条
扫描时间相同就拦截，也不按金额硬编码推断费用名称。详情和 CSV 保留账单结算对象供核查。

页面以“待核收费（正数）”为主要金额，同时展示待核退差、净额和条数。
退差转入已分摊会使待核净额增加，不表示待核收费增加。
恒等式：来源净额 = 可分摊净额 + 待核收费 - 待核退差。


### 排除店铺与自定义分组

包裹试算支持多选排除店铺，分组名称和名单可保存在当前浏览器，套用后点击“应用排除”。
系统不按店名关键词猜测“箔类”等业务分类，也不删除原始收费。分组可以更新或删除。
仅当收费的候选店铺非空、且全部属于排除名单时隐藏；未知归属及混合候选继续保留。
汇总、问题组、列表、详情和 CSV 使用同一规范化名单，导出校验值包含该名单，避免导出范围串用。
页面显示排除条数、正数收费、退差和净额；恢复全部可回看完整结果。分摊比例和分摊原件不重算。
