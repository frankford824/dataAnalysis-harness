# 费项保存与后台重算

## 用户流程

1. 编辑规则并试算当前店，取得费项规则版本。
2. 保存请求只完成规则校验、落库、审计和任务登记，立即返回任务号，不等待任何店铺计算。
3. 页面显示已处理/总店铺数、成功数、失败数、当前阶段及逐店错误。可以离开或刷新页面。
4. 失败项可以单独重试，已完成店铺不重复执行。核算完成不代表原始资料已齐、已经结账或付款。

## 范围与一致性

- 按各平台有效规则的**有序序列**比较差异，包含通用规则；只改备注、操作人或时间不触发金额重算。不依靠店名、金额相近或文本猜测缩小范围。
- 已有账期但仅使用订单台数据的店铺也纳入候选。已归档店铺不自动重算。
- 使用已有 `commission/registry.db` 的 `job` 队列和原 `commission_manager`，没有第二套后台调度器。每次处理一家店，轮换让出执行机会给原订单/提成待办；仍受原全局并发和同店锁约束。
- 保存必须带试算时的 `expected_fee_revision` 和 `request_id`。旧页面不能覆盖新规则；重复请求返回同一任务，不重复写规则和审计。同请求号不能提交不同内容。
- 上一批费项重算进行时，禁止覆盖该批所用规则。失败任务只有在规则版本仍一致时才能重试。
- 使用 preparing 日志先记录保存意图，再原子写配置。重启时核对实际规则版本，已提交的保存继续补齐审计与入队；未提交或被新配置替代的意图不会被重新强行写回。
- 已完成店铺及运行号持久保留；中断的店铺恢复排队。任务的重试历史保留在结果中。
- 已结账指针、人工核定实发不改变。规则 CSV 不作为本次代码发布的覆盖文件。

## API

- `GET /api/fees` 返回 `fee_revision`。
- `POST /api/fees/preview` 返回与试算对应的 `fee_revision`。
- `POST /api/fees` 提交规则、`expected_fee_revision`、UUID `request_id`，返回 `saved` 和 `job`。HTTP 响应不再携带全公司逐月核算大结果。
- `GET /api/fees/jobs` 返回最近任务及逐店进度，取任务自身的持久进度，不借用其他同店任务的进度。
- `POST /api/fees/jobs/{id}/retry` 只重新排队未完成项。

## 验证与边界

后台测试覆盖范围筛选/删除/排序/通用规则、重复提交、旧页面冲突、保存失败、提交后中断恢复、队列轮换、部分失败与单项重试。真实 Vue 组件验证修改→试算→保存→失败提示→重试→成功，另验证刷新后恢复 1/2、75% 进度。

本次不更改金额算法，不通过增大并发或跳过来源校验来提速。大店首次核算仍可能耗时；改善的是阻塞保存、无关全店重算、重复任务和进度失真。历史语料 slow 测试缺少完整本地数据，不计作通过。
