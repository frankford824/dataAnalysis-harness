# 提成弹窗、批量组织与读取性能修复

## 行为

- 实发、店铺选择、结算和批量设置弹窗统一限制为视口高度减安全边距。标题和底部操作固定，仅正文滚动。
- 实发列改为纵向金额、核定状态、操作入口；店铺卡片分离名称、参考金额、编辑入口。
- 批量新增按组织团队分组选人，仅允许选择已登记有效人员；新增人员进入组织页维护。
- 批量支持显式补上级抽成，预览及保存保留 duty/source。merge/remove 保留未修改人员的身份及上级抽成来源。
- 批量只保存商品规则，不再暗中修改店铺默认身份，也不再有“商品保存成功、第二个身份请求失败”的部分成功状态。

## 读取优化

- 店铺文件清单按 store_id/name 索引统计本店与共享文件版本，不聚合全公司的版本历史。
- 账期详情先检查缓存，仅未命中时读取完整状态快照。
- 给旧切片补 overview 时复用现有 commission/products/statement，避免重复 json_each 商品树；原数据更新仍由失效触发器处理。
- 只读生产样本：文件清单新旧结果完全一致，旧查询 194/34/35ms，新查询不足 1ms。补摘要样本查询从 17/15/15ms 降到 3.0/2.7/2.6ms；保留原生切片精度，避免 SQLite JSON 重序列化造成毛利率末位精度变化。
- 上述是查询样本，不等同于整个页面、并发负载或首次迁移的承诺。

## 验证

173 项后端测试、22 项前端测试及构建通过。新增批量 merge 身份与来源保护、定向文件清单结果一致性、旧切片补摘要不重算商品投影的回归。

`ledger/web/tests/payout-flow.html` 用真实组件与 12 人隔离数据验证编辑、滚动、底栏边界与整店保存；`batch-flow.html` 验证组织分组、补上级、预览及只保存商品规则。测试接口全部为隔离数据。

已在实际 1280×720、680×600、390×600 视口检查相关流程。生产发布后继续核对 API 版本、产物哈希、完整接口耗时及冻结数据。
