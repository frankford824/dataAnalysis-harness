# 实际发货成员成本事实 v3

该规则用于订单台暂缺、而上传原件与聚水潭固定取证已经证明实际发货成员的开放店月。它不是人工总成本覆盖，也不改变提成、退货、代发或结账政策。

## 入口与默认状态

- 规则：`jst_physical_source_cost_facts.v3`。规则合同及 SHA 由 `GET /api/automation/rule-contracts` 返回。
- 新增采纳同时要求 `LEDGER_DETERMINISTIC_AUTOMATION_ENABLED` 和 `LEDGER_SOURCE_COST_V3_ENABLED` 启用；默认关闭。
- 必须存在该店、该账期、该版本的已认证人工规则授权，以及有效自动发布范围。
- `POST /api/automation/service-physical-facts` 只接受当前案件、run、输入 SHA、缺口键及上下文、人工补录版本、规则 ID 和幂等请求 ID。金额、数量、来源路径、原始 JSON 和绑定对象不能由请求提交。
- 服务身份需要 `business` 范围及 `approved_action` 能力。服务身份不能批准规则、月结或实发。

资料核验、报价和金融短事务分开。真正采用前再次检查当前输入、授权、冻结状态、原始文件及独立来源证明；决策、授权、回执和重算投递在 Workspace 同一事务内保存。原件、订单台快照及历史金融记录不改动。

## 金额进入原引擎的方式

后端重开原始工作簿、固定取证原始字节和历史报价，再运行独立成员归一器。容器 Split/Merged 状态不改写为 Sent；实际已发货物理成员的身份、SKU、库存件数和原始价格日必须独立成立。缺失的原始风险标记仍为缺失，不能伪造 False。

新事实在重算时生成独立的内存来源行，交同一个原核算引擎执行原有过滤、关联、免成本、代发、退货及聚合规则。已有成本和人工决定优先。系统先从实际计入事实及原始行定位已计入的组件，再只补缺少的组件。例如已有 A 的成本 2、缺 B 的成本 3，结果只能是 5。无法证明组件归属时继续待核，不能用整单总额猜差额。

历史报价与原始库存数量保留 Decimal 字面量，进入原引擎前检查数值可表示性；不对每件或每个物理成员新增分位舍入规则。原件数量（套）与物理成员数量（件）分别保存。只指向旧容器、无法对应实际成员的退货入库记录保持待核，不能在替换来源粒度后悄悄漏掉退货。

没有采用 v3 事实时不会额外运行一次引擎。已有事实必须重新核验真实来源依赖，不能从进程缓存绕过。原始资料哈希相同、run/input nonce 改变本身不导致重新上游抓取；真实来源目标变化仍会失效。

## 开关、到期和撤销

关闭自动化开关或授权自然到期会停止新的事实采纳，不会静默删除已经合法采用的事实或改变原成本。

明确撤销事实会保留原记录并投递开放账期重算；同一请求不能复活已撤销事实，同一个旧授权也不能让自动重试立即重新采用。明确撤销授权会使其相关开放期继续待核。已结账、已核定实发禁止新增采纳；结账历史及实发确认记录继续保护。

## 实际依赖与已结原成本的只读复用

月结刷新只选择当前 run 的凭据中实际采用的 v3 决策 ID，并只刷新真正使用的报价元组，已经有价且未被 v3 替换的兄弟商品不重复取价。后来由有效人工成本决定或完整原始已价来源取代的旧事实仍保留审计记录，但不作为本次金额依赖，也不会因此要求无关的上游刷新。

v3 每次实际计入时，把确实非零计入的逐成员成本输入及该订单原始 native 输入封存为内容寻址 Parquet，挂入同一 run 的来源凭据及保留对象。金额仍由原引擎计算。未计入、排除或零贡献的行不因封存而取得金额准入。

后续开放月份发生实际退货时，可以只读使用已结原月的这些依据。加载器验证冻结 run、原有授权链、所有来源文件及成员归属，核对封存数量、原价、原始行 anchor 与当时实际计入贡献守恒；不重新抓取旧月，不取当前报价，不改旧月 run、状态或金额。之后仍由原退货成本引擎处理实际退货日、每个成员的原销售数量和累计退货上限。当前销售准入规则不能重新裁定已经冻结的原销售成本。整期人工覆盖总额不能被拆成子单成本；缺少逐成员冻结档或成员对应不明时，新月明确待核。

## 月结前的有限上游刷新

本地原始文件 SHA 核验只能证明保留的原始证据，不能证明上游没有更新。

1. 月结预览建立服务端控制的新聚水潭取证代际，固定 reader 执行真实抓取。原事实不重写，物理金额语义变化时保持待核。相同业务语义的新来源原件仍单独保存。
2. 聚水潭刷新通过后，预览创建持久历史报价刷新技术任务。Manager 每轮最多请求 10 个固定公司、SKU、原始日元组，与正常金融工作交替；报价读取进度不会触发整店财务重算。
3. 报价实际响应重新经过原提供者区间解析。与已采纳事实的完整有效区间语义相同时才能通过；价格更正、重叠冲突、登录失效或接口失败均保持待核，不直接覆盖旧事实。
4. 月结提案保存两个刷新任务和精确代际摘要。确认时只回读同一有限捕获及金融 CAS，不能改用任意旧任务。后续新代际、范围变化、来源原件变化或真实金融输入变化均拒绝旧提案。

这证明的是明确有限捕获窗口下的一致性，不承诺跨 ERP 与台账数据库的瞬时“绝对最新”。

## 验证入口与边界

`test_automation_source_cost_v3.py` 覆盖原始单位、正常 SKU/非赠品/真实发货证明、原始标记缺失、极端指数及 Decimal 精度。

`test_source_cost_posting.py` 使用真实原引擎验证已有 A + 缺 B、原过滤条件、整容器既有成本、归属不足、含厘聚合、容器退货及到期/开关/撤销语义。

`test_source_frozen_cost_basis.py` 通过原退货引擎验证同父多成员、超退封顶、现规则改变、整期人工总额拒绝分拆，以及旧月逻辑哈希保持不变。

`test_source_cost_v3_contract.py` 使用真实上传原始字节与固定取证收据验证采纳、幂等、默认关闭、严格写认证、冻结实发、撤销后重试，以及真正报价刷新和代际确认。它是声明的合成接口合同，不是历史金额 golden，也不替代全服务真实样本、独立验收和影子结账周期。
