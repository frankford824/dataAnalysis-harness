# 全链路读取性能修复

## 查询与索引

完整9–20位数字宝贝ID使用精确索引查询；短数字和名称保持模糊搜索，多ID按集合查询。新增活跃方案分段/人员关系读取索引，数据库触发器与规则发布同事务维护，预览回滚同时回滚索引。历史、当前、未来首个分段的人员筛选语义保持一致。新索引是可重建结构，不改变原规则和历史版本。

商品页和计数缓存加入目录变更与实际生效边界，避免目录刷新或未来规则到期后仍显示旧结果。人员汇总及报告配置覆盖查询复用关系索引。目录/方案名称覆盖索引降低扫描大载荷的成本。

## 读取和缓存

趋势、缺口、兼职、未分类费用和旧提成汇总使用摘要；单店/单月支持下推范围。完整详情及审计导出保留原始证据路径。计算历史先按店批量取头信息，消除每条记录读取完整状态。

读取缓存按键合并在途请求，不在全局锁内构建；报表构建同样合并。新增店铺/月依赖时钟：其他店其他月不会使当前店详情失效，但同月跨店收入变化仍刷新兼职分摊。共享文件、配置与模型版本仍使相关缓存失效。

已验证的历史提成产出汇总增加有校验和的持久化派生缓存，键包含计算记录、原证据SHA、文件大小/修改时间及计算代码版本；源文件变化或缓存损坏必须重新验证。人员计数按规则变更时钟和生效边界缓存，姓名等人员信息仍实时读取。派生缓存有容量上限，写入不等待锁，不修改原始金额记录。

报表分页不再夹带完整 store_people。利润首屏只返回商品摘要，点击后加载单商品订单；每页渲染50个商品，但合计、全选和导出仍覆盖完整筛选结果。

## 前端调度

计数防抖、取消旧请求、页面离开停止；组织切人取消旧加载；预取限制为一个在途请求，翻页复用其结果；记忆缓存最多12页，计数缓存24项，账期缓存8项。取消相邻月份的完整详情预取。

## 验证记录

- 定向后端219项通过，前端22项通过；更广的非慢回归1463项通过、14项未运行。
- 真实组件验证：实发全流程、批量组织联动、利润分页与按需订单，控制台无相关错误。
- 同一生产只读快照891个店期，完整结果与摘要的statement/findings/missing_sources/unclassified/quality/cost_review/cost_coverage逐项一致。
- 生产注册表隔离副本初始化索引4.81秒。完整ID搜索133→5.4ms，人员页578→28.8ms，人员计数1023→11.1ms；名称查询约120ms基本不变。对比返回值一致。旧实现也可使用新覆盖索引，因此这些数不是部署前HTTP15秒的同条件倍率。
- 发布前固定50份六月核算、99条人员金额用于上线后逐行摘要校验；冻结598个已结账店期的关联校验。

本地与副本结果不等同于用户浏览器首屏时间。上线后单独记录HTTP未命中、命中及并发样本；不以服务器本机耗时宣称所有设备、所有数据范围已达P95指标。
