# 刷单商品成本及覆盖率

商品成本免计规则使用完整的原始字段：蓝色旗帜，以及卖家备注中的独立 `by` 标记（大小写不敏感）。`by6王娜`、`by 陈慨发空包`均匹配；`baby`、`nearby`不匹配。“买家秀”优先保留正常成本核算。

订单台 `seller_flag_code` / `seller_flag_name` 是全平台原始卖家旗帜，来源为 `jst_order.extra.seller_flag`。历史取价专用 `order_flag` 不作为新原始字段的反例，也不改变上游拼多多取价政策。主单和商品的原始旗帜冲突时保留待核对，不用旧上传表覆盖冲突。

默认 `brushing_scope=platform_order`，每个原平台主单需要独立蓝旗/by依据。单体头只有一个平台主单时可直接核实；合并头使用 `platform_seller_evidence_json`（`jst-member-evidence.v1`）中的独立原始成员记录，核对根订单、店铺、成员主号、原内部订单、来源、单体作用域、时间及凭据摘要。`complete`仅表示资料完整，不表示全组刷单。普通、买家秀、缺失、冲突或仍为合并头的成员不能自动免成本。

只有公司明确确认“当前合并内部单标记适用于全部同店成员”的业务口径后，才能配置 `brushing_scope=internal_order_header`；该模式仍要求同店完整身份、整组商品旗帜一致、备注每个分句均含by且无买家秀/冲突，不用合并关系本身判断刷单。

符合规则、但没有实际商品成本行的已确认销售子单会生成显式“刷单规则确认零成本”核算事实，并保留内部订单号、原始旗帜、备注、同店主单身份和依据摘要。它们计为成本已核实，不进入未覆盖成本清单，不要求人工补零。已有商品成本行仍走相同刷单规则；不改收入、退款、运费、代发支出或刷单费用的各自口径。

判定依据参与输入指纹。旗帜、备注、归属或身份完整度变化会重新核算，不能复用旧结果。结账金额与核定实发保持原有冻结/审计机制；不因补传字段覆盖已结账记录。

订单台 v1.7 增量还支持最新只读采集的 `jst.order_list.seller_flag` / `jst.order_list.remark`，留存 `seller_evidence_hash` 和 `seller_evidence_captured_at`。卖家旗帜、备注变化不能被原有金额内容摘要跳过：独立观测只补传元数据，不重写订单金额、商品、价格或成本。来源改变时，旧成员证明失效，通过正常增量清空后重新核查；不能沿用旧刷单零成本。

独立原单证明由订单台后台恢复，每分钟执行，单轮最多 2 个订单头、12 个未缓存原单读取，调度预算 45 秒，失败退避并释放租约。缺失、冲突保留明确终态，不无限重抓。按需 `/member-seller-evidence/requests` 只入队，不能在台账计算请求中同步抓取聚水潭。后台追踪新订单增量和来源变化，补齐结果仍通过同一订单增量、台账输入指纹及自动重算链路消费；已核定实发不变。
