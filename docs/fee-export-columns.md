# 费用明细的显示与导出

旧的“是否进账/已挂钩”二元字段不能解释通过汇总间接计入的费用。用户导出改为以下主要列，明细页面使用同一显示规则：

- 订单号/商品ID：保留精确标识；全店汇总行明确标为非订单号。
- 来源金额（勿合计）：用于逐条核对，可能同时包含原始明细和汇总，不能整列相加作为账期金额。
- 本行计入金额（合计此列）：保留原有 contribution，按科目汇总可与核算核对；不因改标签重新计算金额。
- 核算状态：本行已计入、全店分摊已计入、汇总分摊已计入、全店汇总已计入、本行未计入；冻结金额及旧留档缺失信息单独说明。
- 核算说明：明确间接分摊行的0是防重复计费，不代表费用未计入，并保留原始计算依据。
- 订单资料匹配（非入账依据）：移到来源字段之后，用明确文字说明，不再用“是/否”。匹配资料不保证属于本期，更不等同于入账。

CSV移除“金额、进账、是否进账、已挂钩、入账路径”这些易混淆的旧列名。旧“计算说明”并入“核算说明”。下载文件名标记“核算状态版”，响应头 `X-Ledger-Export-Schema: fees-v2`。已保存的旧Excel文件不会被修改，须重新导出。对接CSV列名的脚本须使用新表头，不能继续按旧“是否进账=是”筛选；API的原始 counted/linked/contribution 等结构字段保持兼容。

页面默认展示可合计的计入行，“未计入”不包括已含汇总分摊的记录。“全店分摊明细”是已计费用的来源追溯，不能再加到默认合计上。旧留档缺少标记或金额时显示待核对，不补成已计入0。

仅做显示投影，不改留档、核算结果、原始费用、已结账快照或核定实发。
