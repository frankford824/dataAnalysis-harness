# 规则与老板决定（回答“为什么这样算”时引用）

## 历史与权限（硬性）
- 已结账历史不可改：不自动反结账、不覆盖已结结果、不改核定实发（payout_confirmation）、不改冻结兼职（run_labor）。结账后到的新资料只标 stale，等人决定。
- 未知不能变成零：资料缺口不补零、不套用历史月份金额（例：9 月兼职核定资料未上传 → 兼职与利润额保持“未确定”）。
- 参考价/估价/模糊归属不能形成正式金额。自动处理只限开放账期、已批准的动作、精确匹配且有充分原始凭据。
- Agent 不能忽略阻断项、不能反结账、不能改历史金额、不能代替人工确认财务决定（自动化写接口要人工身份）。
- 会动金额的修改：先 propose_change 卡片，用户点“确认修改”后才执行。查数、排查、修程序可直接做。
- 模型花费每月硬上限 2000 元。
- 2026-11-03 老板：局域网 2-3 人使用，取消登录；没点名就不要加门禁/CI/单测。

## 结账
- 财务月底批量确认；已就绪的店可以先结。自动结账每天 02:00 跑最近 3 个已过去的月份：close-batches/preview → confirm，只结检查全通过的店。白天不跑（会拖慢系统）；需要时可让助手 run_auto_close。
- 结账门槛：商品成本覆盖率≥95%、收入挂单率≥95%、已分类≥99.5%、必需资料（订单明细/对账/聚水潭成本/运费）到齐、close_verification 无 hard 问题。
- 常见 close_verification code：input_capture_unverified（请先按当前服务重算）、missing_sources（还缺：运费）、chk_receipt_coverage、chk_no_unclassified、chk_sources_ready、shared_store_identity（共享表N项未确定店铺）、allocation_basis（商品归属待核对）、dropship_scope_evidence/dropship_cost_evidence（代发待核对）、input_parse_errors（源表解析失败/没见过的表头）、required_cost_unresolved、cost_amount_completeness_unverified、profit_unknown、company_revenue_unknown（公司仍有店收入未定，公摊冻结不了）、overhead_total_unknown（兼职核定依据未收到）、commission_incomplete（软）、recompute_pending、stale_run（重新预览）、frozen_refund_recheck_required、unverified_code_change/unverified_model_change（新代码/规则待自动重算复核）。

## 收入、退款、费用
- 利润公式（老板定）：销售收入+销售退款+平台服务费−物流运费+交易赔付+营销费用−发货运费−推广费用−小额打款−刷单−代发成本−聚水潭成本−补发成本。
- 退款按资金流水发生月入账（不是按下单月）。补发成本归原销售月。
- 对账单会重复上传/错月：按流水去重（例：1688 星泽 6 月曾翻倍到 7.38 万，实际约 3.7 万）。
- 保证金-天猫-扣除转移不计；保证金解冻返回不计；保证金锁定、商家集运物流责任货值赔付 → 交易赔付；淘宝联盟佣金代扣 → 营销费用；消费者体验提升计划服务费入账；充值不计；广告充值记“广告费用”。
- 物流运费在源数据是正数，公式里做减法是故意的。
- 科目→损益项归类在“费项”页（dictionary.csv）；未分类金额会阻断结账。

## 成本
- 成本来源：订单台（聚水潭）成本；K 表「聚水潭成本（补充）-店名.xlsx」补价。ERP 0/负成本=缺价（非赠品），赠品明确 0 价算有价。订单台标 is_suspect（如数量 2043 倍）的行成本不计。
- 取消/关闭订单不计成本；HQT01773 等“无需发货”成本 0；邮费补差 SKU 成本记 0；被拆分/合并取代的父单不计履约成本。
- 刷单零成本：需蓝旗标记或备注确认。
- 售后成本：退款成功且货物状态为 买家未收到货/买家已退货/卖家已收到退货 → 该商品成本不计；卖家已收到退款且退款关闭、买家已收到货且退款成功 → 暂计；未列出组合默认计。逐商品排除，不整单。
- 覆盖率分母=应计订单数；低于 95% 不能结账，缺口在 coverage-gaps，可人工补录（cost_line_log）。
- 注册首价（register_first）只作参考，不形成正式金额。

## 公共表与分摊
- 公共表：代发成本、刷单/本金佣金、小额打款、发货运费（按订单号/运单号匹配到店）、售后单。共享表认不出店铺的不回退猜测，留“共享表店铺归属待核对”。
- 运费周表只有运单号，按运单号去重匹配。
- 兼职费用：公司当月总额（/labor 页录入）按各店当月销售收入占比分摊；结账时冻结。
- 推广“全店托管”：总花费−订单明细对应 ID 的稳定成本推广=全店托管部分，按订单明细 ID 条数均摊；推广按原始日期归月。

## 提成
- 规则按店铺×商品 ID；总提成率固定，子提成率之和=总率；按下单时间匹配生效时段（例：某 PDD 店 8/1 前两人做货 3/2 点，之后一人 5 点）。
- 做货产出归做货人；抽点不占销售/毛利/利润。多人做货按点数分。商品无归属按店铺默认人。
- 基数：扣兼职后经营利润；亏损单扣负（deduct）。跨期退款实时计算。
- 应发系统算，实发可编辑并经确认后锁定（核定实发）。
- 例：淘宝汪学成 3.5%、李秋雨 1.5%，1688 姜惠卉 5%，抖音蔡果 5%（以 registry 当前规则为准）。

## 店铺与文件
- 店名「负责人-平台店名」；改名只加别名。文件名必须含注册店名或别名（差一个字/大小写会进 20_需修正）。
- 同名文件=新版本替换；不要改原始文件名。
